办公室是**不同时刻**的协同：你留下一件活，AI 员工在他值班时做完，你回来验收。
它不新增一套后台服务——**执行的是开着的 SLATE Teams 页面本身**。

:::note 办公室有两面
顶栏「办公室」这一页默认落在**对话面**；本章讲的是切到**工位**以后的这一面。
两面的切换在页面右上角，对话面与工位仍属于同一页。
:::

:::warning 应用关了，活就不跑
后端只负责排队，不执行任何一件活。所以办公室需要有一台机器上的 SLATE Teams 是开着的，
那一个页面就是当班的人。关掉应用，活会安静地留在队列里，等下一次有页面在。
:::

## 面板长什么样

左边是**花名册**和一张**工位平面图**（谁在忙、谁空着、谁在递话，一眼看得见），
中间一个递话框可以直接「交给」某位、「贴出来」给所有人，或者「交办」一条活。
右边五页签：**动态**、**等你拍板**、**值班表**、**岗位**、**站会与绩效**。
这一章讲「岗位」和「值班表」，后两页在[像人一样工作](./08-office-work.md)与[门禁与账](./09-office-gates.md)。

## 招人

「招聘」里两种来路：**按模板招一位**（内置四位：研究员、工程师、审校、值班管家），
或者从零填一只新同事。一位员工身上你要定这几件事：

| 字段 | 它决定什么 |
| --- | --- |
| 名字 / 头像 / 色相 | 同事之间靠名字寻址，**不能重名** |
| 岗位一句话 / 目标 / 职责 | 他干什么、朝哪儿使劲，也是分诊时判断"该不该他办"的依据 |
| 模型 / 轮数 / 项目 | 用哪只模型、一趟最多跑几轮、活落在哪个项目根 |
| 审校 | 他的交付要不要过人、由谁过；选「不设审校（交付直接给你）」就直接给你 |
| 每日预算 | 一天能花多少 token，花满就熔断（见[门禁与账](./09-office-gates.md)） |
| 托管 | 他值班时按哪一档审批跑 |

不想要了按「解雇」——人从名册上走，他办过的活和说过的话**留在账上**，绩效那一行标「已离职」。

## 排班

「新增值班」给一位员工排一条班。触发方式两类：

- **每日定时 / 每隔几分钟 / 一次** —— 时钟到点就来看。
- **事件触发** —— 仓库有提交、盯的路径有文件变更、自检脚本变红、Git 推送、外部回调。

到点了**不等于要动**。每条班可以配**守卫条件**，最常见的两条：

- 「手上待办不超过几条」——0 的意思就是**手上没活才动**。
- 「只在某个时间窗里才排」。

守卫读不出条件、或者条件已不认识，都会在面板上写成一行原因，而不是默默跳过。
:::note 为什么不是到点就动
到点就动会让一个员工在上一件还没做完时又领一件，队列越堆越长。
守卫把"该不该动"变成一条可读到答案的检查。
:::

## 交付队列

花名册上每位员工一个状态——**空闲**、**在忙**、**下班**——后面挂着几个计数：
待办、等你、待审校、退回、预算已满。活的状态是这几种，看得懂就够了：

| 状态 | 含义 |
| --- | --- |
| 排队中 | 已排上，等一个开着的页面来领 |
| 在忙 | 有页面正拿着他在做（带租约，崩了会被重新领走） |
| 待审校 | 做完了，等审校人过 |
| 等你 | 需要你拍板的事，列在「等你拍板」那一栏 |
| 受阻 | 卡住了，后面写着**受阻于什么** |
| 已定论 / 没跑成 | 做完了 / 跑坏了，坏因写在这一行 |

任何一件"没办"都必须有一行能被读到的原因——没有静默重试，也没有静默丢弃。
