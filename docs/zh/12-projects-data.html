项目、备份与账本

Teams 的东西分三层：视野（正在看哪个项目）、记录（对话数据库里的表）、 配置（data/ 下那些文件与项目里的 .slate/）。一次备份只搬得动前两层的一半。

#项目与工作区

  • 单目录项目：项目路径就是那个目录。工作区：一个宿主目录存配置，成员是若干彼此无关的文件夹。
  • 工作区的宿主目录落在 data/workspaces/<名字>，配置写在它的 .slate/config.json 里，只有三样： 性质、成员清单、当前根。成员写相对路径时按宿主目录解析，所以整个工作区连配置拷走也不散架。
  • 当前根任何时刻只有一个：切根只改配置里那一项，文件、Git、终端的工作目录跟着一起换。 配置的读写位置另记一处，所以工作区的配置不会被串改进某个成员自己的 .slate/。
  • 在册的项目全部留在 data/projects.json，正在看的那一个仍是唯一的。项目身份由宿主目录的 绝对路径派生——目录搬走身份就变，所以每条记录还带一份别名，供你手工把老会话归回来。
  • 会话按项目 id 认归属，不按名字：改名、重名、搬家都不该把历史甩出去。
  • SLATE 私有的每项目数据在 data/projects/<id>/，绝不写进你的仓库。

#备份里到底有什么

导出是一个 JSON（带版本号），三段：后端表、浏览器本地那一份、团队历史列表。后端那三段是这些表：

段表装的是什么
对话conversations、messages会话与消息，含归档过的
记忆与素材memories、prompt_snippets长期记忆、提示词素材
议事四张team_sessions、team_turns、team_attendees、team_inbox每场的行头与名册快照、发言全文、票据（只存 sha256）、待代收的发言
账本两张runs、tool_events每一趟的账与工具调用事件；星图与"这一轮改了哪些文件"都从这份数
办公室两张office_jobs、office_messages交付队列与工位传话
按天记账daily_usage每天的 token；少了它，恢复完会话齐全而活跃度热力图一片空白
名册三张employees、employee_duties、employee_notes员工、值班表、他自己的备忘
后面这几组是 Teams 比上游多出来的

少一张的症状永远一样：备份看着齐全，恢复后那一块全空。所以新增一张表必须当场表态 它是记录还是配置——归进哪一份清单，不表态就有自检脚本判红。

#恢复时的两个顺序坑

  • 先建表，再合并。议事、账本与办公室的表都由各自端点首次触达时才惰性建起来；一台从没开过 团队、也从没招过员工的干净机器上它们根本不存在。导入前不建，存在性检查会把这些一律当成 "没数据"跳过——报 0 条，界面照样说"恢复完成"。
  • 只并新，不覆盖。按主键或自然键插入，已存在的整行跳过；想拿备份盖掉现有内容，这条路不走。 发言与工具事件两张还要丢掉自带的行号再插：同一笔发言在两台机器上是同一个（场次，序号）， 照搬会撞上本地新写的那行并被静默吞掉。
  • 导入完成后页面会重载一次，本地那半截要重载才生效。

#两种"清空"不是一回事

你点的地方清掉了留着
侧栏「任务」→ 管理 → 清空全部会话与消息议事正文、交付历史、名册与值班表；只把指向这些会话的引用抹空
设置 → 存储空间 → 清空对话会话、消息、议事四张、账本两张、办公室那两张、按天记账，随后压缩数据库员工、值班表、他自己的备忘；记忆与素材；知识库
后面那一刀带得动议事与交付

确认框里就得把这句话写全，只说一句"清空对话"是骗人。名册与班是配置，不是对话记录， 所以一个人说"清空对话"时不该顺手解雇员工、取消他的班。

#故意不进这份 JSON 的东西

data/ 下的配置与二进制一概不在备份里：桌面共享设置 desktop_state.json、MCP 的端点与密钥 mcp_servers.json、定时任务 scheduled_tasks.json、自定义技能 skills/、专家包 experts/、 流程说明书 actions/、全局宪法 constitution.json、知识库 knowledge.db、背景图与导入字体 data/theme/、在册清单与工作区宿主 projects.json、workspaces/。 项目自己那份 <项目>/.slate/ 跟着代码库走，本来就不该进备份。

备份文件是明文
