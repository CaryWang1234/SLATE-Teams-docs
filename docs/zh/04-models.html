模型与用量

#模型从哪来

内置模型清单在后端的注册表里（backend/routers/proxy.py），前端启动时取过来填进选择器，分三组： 国际模型、国产模型、本地模型。

按模型 id 的前缀认厂商就够了：gpt-、claude-、gemini-、deepseek-、kimi-、qwen-、glm-、 doubao-、MiniMax-、ernie-；本地那一条的 id 就叫 local（指向 Ollama / LM Studio）。 每家的请求地址与标称上下文窗口都写在注册表里，不用你填。

同一家厂商的档位口径不一样

思考档位是按厂商给的：有的能关、有的是强制思考（Kimi K3、GLM-5.3 就没有「关」这一档）、 有的只有开关没有强弱。所以那颗「推理强度」滑杆上的档位会随模型变。

#密钥存在哪

设置 → 模型配置 → 「内置模型密钥」逐家填；顶栏那颗「密钥」按钮直接打开设置页。 发请求时由本机后端拿着它去那家厂商鉴权。

它落在本机 data/desktop_state.json 的 modelKeys 那一项里，浏览器本地状态同时存一份。

备份里有你的密钥

设置页写得很直白：备份是「后端数据库 + 本地设置」打成的单个 JSON 文件。本地设置就含 modelKeys。 备份文件要当机密对待——别发到群里、别丢进公共网盘、别提交进仓库。

手机端不用重填

局域网遥控那侧读的是同一份 desktop_state.json，配过一次，手机跟着走。

#上下文预算

用量条那个百分比的分母不是模型标称窗口，是这一场的预算。口径只有一条：

  • 「自动」（默认档）= 该模型标称窗口 × 0.8，向下取整，不吸附到滑杆档位。
  • 窗口完全缺失的模型，才用设置里那个「上下文 Token 上限」兜底（默认 64000）。
  • 你手动设过的值优先，但不会超过该模型的标称窗口。

为什么留两成：剩下的要给输出。吸附到整档会把 128K / 200K / 256K 压成同一个数， 更麻烦的是小窗口模型凑不满最低一档只能返回 0，等于全额占满窗口、一点输出余量都不留。

预算同时喂给两处：上下文条算到哪儿算满、自动压缩在第几轮触发。两边是同一个数， 所以不会出现「看着没满就压缩了」。

要单独调某个模型：模型配置里该行的「最大上下文」，滑杆粗选、旁边的数字框填精确值； 本地与自定义端点还能「探测窗口」，让程序去问端点自己报多大。预算与标称窗口不一致时， 用量条的悬浮层会把两个数都写出来。

#用量条读法

对话页会话区上方那条，从左到右：

段它是什么
模型名当前模型；没配密钥时旁边亮一个警告标
消息这一场的消息条数
输入累计 prompt token
输出累计 completion token
总计两者之和
上下文已占用 token 数 + 占预算的百分比进度条

「上下文」那一段可以点，点了直接跳到设置页这一档的预算滑杆。停在用量条上会展开上下文构成， 按五个桶分：系统提示词 / 工具目录 / Skill 注入 / 工具调用与结果 / 对话消息，各带占比。

数字是估算

token 按约 3 字符 / token 估。可信的是占比与趋势，不是与上游账单逐位一致。

#换模型与加厂商

  • 换模型：对话页输入区工具行的模型下拉。它是全局的一档——切会话不会换模型， 但每场对话各自记着自己的用量。
  • 加厂商：设置 → 模型配置 → 「+ 添加模型」。请求模式三种：OpenAI 兼容（自动拼 /chat/completions）、 Anthropic（/v1/messages + x-api-key）、curl 直连（Base URL 填完整端点地址）；再填 Base URL、 API Key（可选）、Context Window。
  • 备份与恢复：设置 → 数据备份与恢复，按 id 合并导入，不覆盖已有数据。详见 项目与数据。
